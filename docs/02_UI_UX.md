# 빌드로그 UI/UX 명세

갱신일: 2026-09-26 · 상태: **사용자 결정 반영 / 구현 전** · 제품 기준: [01_PRODUCT_SPEC.md](01_PRODUCT_SPEC.md)

모든 화면은 기획용 ASCII 구조다. 구현 화면이나 최종 시각 디자인이 아니다. 두 차례 문답으로 핵심 범위·첨부 한도·자유 버전·지역 공개·Featured·삭제 유예 정책을 반영했다. 댓글·별도 알림함은 MVP에서 제외한다. Q15~Q24와 연속 카드 접기를 반영했다 [확정, 사용자 2026-09-26]. GPT 구체 모델·월 예산·문의 이메일 주소와 7일 관찰 후 주간 다이제스트 판단은 미정이다.

## 1. 정보 구조와 공통 이동

```text
빌드로그
├─ 피드: 전체 / 팔로잉
├─ 탐색: 검색 / 분류 / 기술 태그
├─ 게시: 프로젝트 선택 → 작성 → 게시물 상세
├─ 프로젝트: 소개 / 스크린샷 / 개발 타임라인 / Release
├─ 프로필: 소개 / 프로젝트 / 선택적 위치
├─ 내 공간: 저장 / 프로젝트 관리 / 설정 / 결제내역
└─ 관리자: 콘텐츠 파이프라인 / 신고 / 결제 확인
```

데스크톱은 좌측 탐색과 중앙 콘텐츠, 필요한 화면만 우측 보조 영역을 둔다. 모바일은 피드·탐색·올리기·내 프로필을 하단 탐색으로 제안한다. 결제와 작성 화면에서는 입력을 가리지 않도록 하단 탐색을 접는다. 비회원도 공개 피드·프로젝트·프로필을 볼 수 있다.

## 3. 화면별 명세

### SCREEN-001 피드

```text
┌─────────────────────────────────────────┐
│ 빌드로그        [검색]        [내 프로필] │
│ [전체] [팔로잉]                          │
│ [오늘 뭘 만들었나요?             올리기] │
├─────────────────────────────────────────┤
│ 아바타  이름 @handle        게시시각  ⋯ │
│ ┌─────────────────────────────────────┐ │
│ │       스크린샷 / 영상 미리보기       │ │
│ └─────────────────────────────────────┘ │
│ [좋아요]              [공유] [저장]     │
│ 오늘 만든 화면에 대한 짧은 설명         │
│ [프로젝트명 · 버전 →]                   │
│ [이 프로젝트의 이전 게시물 N개 펼치기]  │
│ Release 포함 (접힌 글에 있을 때)        │
├─────────────────────────────────────────┤
│ 공식 · 오늘의 만들기 주제               │
│ 바뀐 화면을 소개해 보세요. [게시하기]    │
└─────────────────────────────────────────┘
```

- 사용자 게시물의 프로젝트 칩은 프로젝트 상세, 작성자 정보는 프로필, 콘텐츠는 게시물 상세로 연결한다. 서로 겹치는 클릭 영역을 만들지 않는다.
- 전체·팔로잉 자연 피드에서 같은 프로젝트 게시물이 연속 2건 이상이면 최신 1장과 “이 프로젝트의 이전 게시물 N개 펼치기”를 보여준다. 펼치면 원래 위치·최신순 그대로 보이고 접힌 게시물에 Release가 있으면 “Release 포함”을 표시한다. 공식 카드·광고는 접지 않으며 Q4 정렬·`published_at`·프로젝트 타임라인 전체 기록을 유지한다. [확정, 사용자 2026-09-26] (D2·K-12). 한 페이지 응답 안에서만 접는 방식은 [확정 원칙 / 기본값은 제안, 구현 시 변경 가능] [기본값 제안]이다.
- 새 게시물은 새로고침 안내로 반영하고 읽던 위치를 갑자기 밀지 않는 안을 제안한다. 초기에는 수동 새로고침으로 충분하다.
- 로딩: 카드 골격. 비어 있음: 실제 글이 없다는 안내와 공식/데모 콘텐츠. 팔로잉이 비면 프로젝트 탐색 링크. 오류: 읽던 목록을 유지하고 다음 페이지 재시도.
- 좋아요·저장 실패는 이전 상태로 되돌리고 이유를 알린다. 공식/데모/광고 배지는 제목 근처에 둔다. Q3에 따라 기본 카드의 반응 숫자·댓글 버튼·알림함 버튼은 표시하지 않는다.
- Q14에 따라 메인은 사용자 글 5개당 공식 카드 1개를 섞고 부족하면 공식·데모를 보충한다. 팔로잉은 팔로우한 프로젝트의 게시물만 표시하고, 비어 있어도 공식 카드로 대신 채우지 않는다.

외부 소식 카드는 사용자 게시물과 다음처럼 구분한다.

```text
┌─────────────────────────────────────────┐
│ 공식 · 인디 소식  (또는 업계 소식)      │
│ 소식 제목                               │
│ 출처 이름 · 원문 게시일                  │
│ 출처에 근거한 짧은 한국어 요약           │
│ [원문 읽기 ↗]       [포럼 토론 보기 ↗]  │
└─────────────────────────────────────────┘
```

- 카드의 “공식”은 빌드로그 편집 콘텐츠 표시다. 외부 작성자를 빌드로그 가입자 프로필로 연결하거나 소개된 외부 프로젝트에 내부 프로젝트 칩을 자동 생성하지 않는다.
- 원출처·원문 게시일과 카드 발행일을 구분한다. 원문은 외부 기사/제작자 글, 토론은 해당 포럼 토픽으로 연결한다. 토론이 없으면 버튼을 생략한다.
- 요약/슬라이드는 피드 안에서 열람하고 “원문 읽기”는 외부 이동임을 표시한다. 사용자 게시물 상세 `/posts/[id]`로 외부 소재를 연결하지 않는다.
- 제목·링크만 수집한 소재는 “링크 소개”로 표시하며 본문을 요약한 것처럼 보이지 않게 한다. 원문이 삭제되면 사용할 수 없음 상태와 운영 검토를 제공한다.
- 내부의 “이번 주 프로젝트” 카드만 실제 공개된 빌드로그 프로젝트 페이지로 연결한다. 피드 혼합은 Q14 확정 정책을 따르며, 공식 카드의 좋아요·저장 제공 여부는 후속 결정이다.

### SCREEN-002 로그인·첫 프로필

```text
┌──────────────────────────────────────┐
│ 빌드로그                             │
│ 개발 과정을 공유하는 프로젝트 SNS    │
│ [GitHub로 계속하기]                  │
│ [Google로 계속하기]                  │
│ 가입 안내·약관·개인정보 안내          │
├──────────────────────────────────────┤
│ 표시 이름 [                      ]  │
│ 핸들      [@                     ]  │
│                   [프로필 만들기]   │
└──────────────────────────────────────┘
```

- 로그인 진입 전 열던 공개 페이지와 의도한 행동을 기억한다. 외부 URL로 무제한 복귀시키지 않는다.
- 최초 가입자는 프로필 완료 후 프로젝트 생성, 기존 회원은 원래 페이지로 돌아간다. 팔로우·결제처럼 의도가 분명하면 그 화면으로 복귀한다.
- 로딩: 인증 이동/확인 중. 오류: 제공자 실패·핸들 중복을 구분. 취소: 다시 로그인하거나 구경하기. 중복 프로필 생성 금지.
- GitHub·Google 로그인 버튼은 Q1에서 확정했다. 이메일 가입 화면은 MVP에 추가하지 않는다. 계정 연결은 Supabase Auth의 기본 동작을 따르고 소유 확인 없는 임의 병합은 금지한다. 수동 연결 UI는 MVP에서 제외한다. [확정, 사용자 2026-09-26] (Q22)

### SCREEN-003 프로젝트 생성·편집

```text
┌──────────────────────────────────────┐
│ 프로젝트 만들기                 닫기 │
│ 이름         [                    ] │
│ 한 줄 소개   [                    ] │
│ 사용 기술    [검색] [태그] [+]       │
│ 추가 정보 ▾                         │
│ 분류         [미분류 / 앱 / 웹 / 게임]│
│ 대표 이미지·스크린샷  [추가]        │
│ GitHub / 웹사이트   [             ] │
│ 개발 단계  [개발 중 / 베타 / 출시]  │
│                  [프로젝트 만들기] │
└──────────────────────────────────────┘
```

- 처음에는 이름·소개·기술에 집중한다. 추가 정보가 없어도 프로젝트와 첫 게시를 만들 수 있는 안을 제안한다.
- 생성 성공 후 프로젝트 페이지에 “오늘 만든 것을 올려 보세요” 동작을 둔다. 편집 성공은 같은 페이지로 돌아간다.
- 오류: 필수값·허용하지 않는 URL·업로드 실패를 입력 옆에 표시. 저장 중 중복 제출 방지. 변경한 채 이탈하면 폐기 여부 확인.
- 삭제는 편집 화면의 별도 위험 영역에 둔다. 영향을 받는 게시물·활성 노출을 안내하고 결제 정리가 필요한 경우 내역으로 연결한다.

### SCREEN-004 게시물 작성

```text
┌──────────────────────────────────────┐
│ 오늘 뭘 만들었나요?             닫기 │
│ 프로젝트 [작은 타이머 ▾]             │
│ ┌──────────────────────────────────┐ │
│ │ 짧은 설명이나 링크를 입력하세요  │ │
│ │                                  │ │
│ └──────────────────────────────────┘ │
│ [이미지/GIF 추가]                    │
│ 첨부 미리보기                 [삭제] │
│ 링크 확인 중 / 카드 / 원본 링크      │
│                              [게시] │
└──────────────────────────────────────┘
```

- 이미지 붙여넣기·파일 선택, 링크 붙여넣기를 같은 입력 흐름에 둔다. 글·첨부·링크 중 하나 이상이면 게시 가능하며 텍스트만도 허용한다. 본문 2,000자 카운터, 이미지/GIF 합계 4개, 정적 파일 10MB·GIF 20MB·전체 40MB의 한도와 남은 용량을 안내한다(Q9 후속).
- URL이 여러 개면 대표 카드 1개를 사용자가 바꿀 수 있게 하고 나머지는 일반 링크로 표시한다. 파일 초과·잘못된 파일은 해당 첨부의 오류로 표시하며 다른 입력을 지우지 않는다.
- 프로젝트가 없으면 입력을 잃지 않도록 프로젝트 생성 경로를 제공한다. 선택 가능한 프로젝트가 없는데 게시 버튼만 실패시키지 않는다.
- 업로드 중 진행·취소·재시도, 미리보기 실패의 원문 링크 대체, 권한 상실·세션 만료를 구분한다.
- 성공 후 생성된 게시물 상세와 연결 프로젝트를 보여준다. 실패/로그인 복귀 후 입력 복원 범위는 구현 전에 정한다. 장기 로컬 저장은 별도 기능으로 가정하지 않는다.

### SCREEN-005 게시물 상세·신고

```text
┌──────────────────────────────────────┐
│ ← 피드    작성자 @handle           ⋯ │
│ 원본 비율 미디어 / 영상 / 링크 카드 │
│ [좋아요] [저장] [공유]              │
│ 게시물 내용                         │
│ [프로젝트명 · 버전 →]   게시일      │
│ ⋯ 내 글: 편집 / 삭제               │
│ ⋯ 다른 글: 신고                    │
└──────────────────────────────────────┘
```

- 공유 URL의 단독 진입에서도 프로젝트 맥락을 알 수 있어야 한다. 삭제/숨김은 이유를 과도하게 공개하지 않는 사용할 수 없음 상태로 표시한다.
- 삭제 확인은 되돌릴 수 있는지와 영향을 명시한다. 신고는 사유 선택·선택적 설명·제출 결과를 제공하고 신고자 정보를 공개하지 않는다.
- 미디어 로드 실패 때 본문·링크·프로젝트 이동은 계속 사용 가능하다.
- 본인 보기에서는 해당 게시물의 실제 좋아요 수·저장 수와 본인 프로젝트의 팔로우 수를 표시한다. 다른 사람이 보는 상세·기본 카드에는 본인 통계를 노출하지 않는다. [확정, 사용자 2026-09-26] (D7·Q19)

### SCREEN-006 프로젝트 상세

```text
┌──────────────────────────────────────┐
│ 대표 이미지                         │
│ 프로젝트명       버전 / 개발 단계   │
│ 한 줄 소개                          │
│ 만든 사람 →       [프로젝트 팔로우] │
│ [기술] [기술]   [GitHub] [웹사이트] │
│ 스크린샷  [1] [2] [3]               │

├──────────────────────────────────────┤
│ 개발 타임라인                [전체] │
│ 날짜  [Release] 버전·변경 내용      │

```

- 본인 프로젝트 관리에서 본인 게시물·프로젝트의 좋아요 수·저장 수·프로젝트 팔로우 수를 표시한다. 본인에게만 보이며 공개 기본 카드 숫자 숨김(Q3)은 유지한다. [확정, 사용자 2026-09-26] (D7·Q19). 프로젝트 타임라인에는 연속 카드 접기를 적용하지 않고 전체 기록을 유지한다. [확정, 사용자 2026-09-26] (D2·K-12)
- Q3에 따라 프로젝트를 팔로우한다. 제작자 링크는 프로필 열람으로 연결하며 개발자 팔로우 버튼은 표시하지 않는다.
- 비어 있음: 프로젝트는 공개하되 타임라인 첫 게시 안내. 스크린샷·링크·Release가 없으면 해당 빈 장식을 만들지 않는다.
- 로딩: 소개와 타임라인 분리. 오류: 해당 영역 재시도. 삭제/숨김/권한 없음: 공개되지 않은 내용이나 과거 결제 정보 노출 금지.

### SCREEN-007 Release 작성

```text
┌──────────────────────────────────────┐
│ Release 게시 · 프로젝트명           │
│ 버전          [                  ] │
│ 제목          [                  ] │
│ 바뀐 점       [                  ] │
│ 관련 링크     [                  ] │
│ 첨부          [추가]               │
│                         [Release 게시]│
└──────────────────────────────────────┘
```

- Release는 버전·제목·변경 내용을 담는 게시물 유형이며 별도 버튼으로 작성한다. 버전명은 개발자가 자유롭게 입력·수정한다. `v0.6`, `Beta`는 예시이며 형식·숫자 순서·중복 금지 경고를 강제하지 않는다(Q10 자유 원칙).
- 버전명이 같아도 서로 다른 Release를 만들 수 있다. 중복 클릭으로 같은 요청이 여러 게시물이 되는 것은 별도 오류로 방지한다. 필수 내용 누락·삭제된 프로젝트·중복 제출을 구분하고 성공 후 해당 Release로 이동한다.

### SCREEN-008 개발자·팀 소개 프로필

```text
┌──────────────────────────────────────┐
│ 아바타  표시 이름 @handle            │
│ 소개 / 팀명                         │
│ [외부 링크]             [공유]      │
│ 공개한 시·군·구                     │
│ 지도: 공개 설정이 있을 때만 표시    │
├──────────────────────────────────────┤
│ 프로젝트                            │
│ [프로젝트 A] [프로젝트 B]            │
│ 본인만: [프로필 편집] [저장 목록]    │
└──────────────────────────────────────┘
```

- Q2에 따라 프로젝트는 한 계정이 관리한다. 팀명은 소개 정보이며 멤버 초대·공동 편집·소유권 이전 UI는 MVP에 포함하지 않는다.
- 지도는 시·군·구의 대표 좌표를 보여준다. 실패 시 공개를 선택한 지역 텍스트로 대체한다. 위치가 없거나 비공개면 지도를 위한 빈 공간을 만들지 않는다(Q11).
- 프로필 본인 보기에는 본인 게시물·프로젝트의 좋아요 수·저장 수·프로젝트 팔로우 수를 표시한다. 다른 사람의 프로필 열람에는 제공하지 않으며 기본 카드 숫자 숨김(Q3)을 유지한다. [확정, 사용자 2026-09-26] (D7·Q19)
- 프로젝트 없음은 제작 시작 전 상태로 표현하며 가짜 프로젝트로 프로필을 채우지 않는다.

- 결제 확인 뒤에는 “시작 대기”와 “노출 시작”을 제공한다. 시작 성공 후 시작/종료 시각과 취소 가능 여부를 갱신한다. 시작·취소가 경합하면 서버가 확정한 한 상태를 표시한다.
- 결제창 중단은 “결제가 완료되지 않았습니다”로, 결제 완료 후 취소는 별도 상태로 표현한다. 실패 코드 원문만 보여주지 말고 가능한 다음 행동을 안내한다.

### SCREEN-013 결제내역·취소

```text
┌──────────────────────────────────────┐
│ 결제내역                            │
│ 프로젝트 / 상품 / 결제일 / 금액    │
│ 결제: 완료      노출: 시작 전       │
│ [상세]                 [결제 취소] │
├──────────────────────────────────────┤
│ 상세: 주문번호 / 노출 기간 / 상태  │
│ 취소 가능한 금액·조건               │
│ 취소 사유 [                    ]   │
│                 [돌아가기] [취소] │
└──────────────────────────────────────┘
```

- 결제 상태와 노출 상태를 따로 보여준다. 취소 요청 중·결과 확인 중·취소 완료를 구분한다.
- 시작 대기 주문의 상세에도 `[노출 시작]`을 제공한다. 결제 결과 화면을 닫았어도 내역에서 시작할 수 있고, 취소 확인 중에는 시작 버튼을 비활성화한다. 운영자 취소가 완료되면 노출도 “취소됨”으로 표시한다.
- 시작 전에는 사용자가 전액 취소한다. 시작 후에는 사용자 취소 버튼을 제공하지 않고, 미제공·서비스 오류의 경우 운영자 확인을 안내한다(Q12). 운영자는 사유를 기록하고 전액 취소할 수 있다. 취소 금액·수수료를 임의로 계산하지 않는다.
- 내역 없음과 로딩 실패를 구분하며, 로그인한 구매자만 조회한다.
- 활성·시작 대기 주문이 있는 프로젝트는 추가 구매 불가임을 안내하고, 결제 후 30일 미시작 주문은 운영자 전액 취소 대상으로 표시한다(30일은 Q13 상수 재사용 [확정 원칙 / 기본값은 제안, 구현 시 변경 가능] [기본값 제안]). 자동 노출 시작이나 취소 완료로 오인시키지 않는다. [확정, 사용자 2026-09-26] (D4·Q16)

### SCREEN-014 관리자 콘텐츠·신고

```text
┌────────────────────────────────────────────────┐

```

- 승인 전 초안과 실제 공개 화면을 구분한다. 예약·게시 시각은 KST로 표시하고 일일 상한은 KST 00:00 기준으로 안내한다. 지연·재시도는 원래 날짜 집계를 유지한다. [확정, 사용자 2026-09-26] (Q23)
- 생성/게시 실패는 원고를 유지하고 실패 단계와 재시도를 제공한다. 승인 후 수정하면 재검수 대상으로 돌아간다.
- Q5에 따라 수집 소스 목록·사용 여부·마지막 성공/실패, 수집된 소재·중복 제외 사유, AI 생성 상태·모델·사용량을 확인할 수 있어야 한다. 생성 실패와 예산 초과는 별도로 표시하고 자동 게시로 우회하지 않는다.
- 원문 링크·원문 기준 날짜·AI 초안을 나란히 확인한다. 생성 전 소재 선택, 생성 후 편집·반려를 지원한다. 하루 1회 수집·최대 5개 AI 초안·승인 후 최대 2개 게시(Q8)의 오늘 사용량과 남은 한도를 표시한다. 초기 허용 소스 4개는 Q15 확정이며 모델·월 예산 설정은 미정이다.
- 신고 상세에는 대상·사유·공개 상태·조치 내역·숨김/복원. 결제 확인에는 주문·결제·노출 불일치를 표시한다. 일반 회원은 화면과 API 모두 접근할 수 없다. 사용자 본인 계정에 명시적으로 부여한 운영자 역할만 사용하며 승인·게시·숨김·복원·취소 기록의 조치 종류·사유·시각·조치자·대상 ID를 확인한다. [확정, 사용자 2026-09-26] (Q18/Q24)

### SCREEN-015 알림 — 이후 범위

Q3에서 MVP 제외를 확정했다. 아래는 이후 재검토용 구조이며 이번 구현 대상이 아니다.

```text
┌──────────────────────────────────────┐
│ 알림                         [모두 읽음]│
│ 팔로우한 프로젝트의 새 게시물 →     │
│ 내 글의 댓글 →   (댓글 채택 시)      │
│ 결제 처리 결과 → (알림 범위 채택 시) │
└──────────────────────────────────────┘
```

- MVP에는 이 경로와 벨 아이콘을 만들지 않는다. 프로젝트의 새 글은 팔로잉 탭에서 확인한다. 결제 결과는 결과 화면과 내역에서 확인한다.
- 이후 도입할 때 사건 종류·읽음·보존 기간·빈 상태·대상 삭제·중복 사건·자기 행동 제외를 새로 결정한다. 이메일·푸시 발송도 이후 범위다.

## 4. 공통 상태·상호작용

| 상황 | 동작 |
|---|---|
| 첫 로딩 | 레이아웃 높이를 유지하는 골격과 필요한 텍스트. 무한 스피너로 상태를 숨기지 않음 |
| 추가 로딩 실패 | 기존 콘텐츠 보존, 실패한 부분만 재시도 |
| 제출 중 | 중복 제출 방지, 진행 상태 안내, 성공 확인 전 입력 제거 금지 |
| 인증 만료 | 입력 복원 가능성을 유지하고 로그인으로 안내 |
| 권한 부족 | 변경을 막고 사용할 수 있는 경로 제공. 비공개 데이터 유출 금지 |
| 빈 상태 | 현재 데이터가 없음을 정확히 설명하고 관련 다음 행동 제공 |
| 삭제·숨김 | 모든 진입 경로에서 같은 공개 상태. 소유자/운영자의 안내는 별도 |
| 되돌릴 수 없는 동작 | 대상 이름·영향·현재 거래 상태를 보여주고 확인 |
| 알림 메시지 | 오류는 필드와 페이지에, 완료는 상태 영역에. 색만으로 구별하지 않음 |

사용자 문구는 한국어 존댓말과 구체어를 사용한다. “기록의 여정” 대신 “게시물을 올려 보세요”처럼 행동을 명확히 한다. 서비스 미운영·테스트 결제·데모 상태를 현재형 문구로 감추지 않는다.

## 5. 디자인 토큰과 적용 경계

핸드오프 §6과 소개 사이트 `DESIGN.md`를 출발점으로 사용한다. 아래 값은 브랜드를 유지하기 위한 기준이며 앱의 반응형·입력 컴포넌트는 별도로 검증한다.

| 역할 | 값 / 규칙 |
|---|---|
| 강조 | `#1e4fd8`, pressed `#173fb0`, soft `#e7edfc`, soft 위 보조 글자 `#3f5aa8` |
| 글자 | ink `#111111`, body `#33332e`, mute `#62625b`; `#91918c`는 장식에만 사용 |
| 바탕 | canvas `#ffffff`, soft `#fbfbf9`, card `#f6f6f3`, hairline `#dadad3` |
| 좋아요 | `#ef4b5f`, 선택된 하트에만 사용 |
| 글꼴 | Pretendard + 시스템 한글 글꼴, 필요한 라이선스와 파일 확보 후 적용 |
| 크기 | 12/14/16/18/22/40/52px. 앱 버튼은 16px 제안. 소개 사이트의 15px 예외는 가져오지 않음 |

## 6. 접근성·반응형 확인 기준

- 키보드로 게시·프로젝트 선택·첨부 제거·모달 닫기·결제내역 이동이 가능하다. 모달 진입/종료 때 포커스를 관리한다.
- 모든 입력에는 보이는 라벨, 아이콘 버튼에는 이름, 상태에는 보조기기 알림을 제공한다.
- 피드 이미지에는 맥락에 맞는 대체 설명, 영상에는 제목과 원본 링크를 제공한다. 자동 재생 소리를 사용하지 않는다.
- GIF·움직임은 정지 동작과 `prefers-reduced-motion` 대응을 검토한다.
- 작은 화면과 확대 상태에서 가로 넘침·버튼 겹침·하단 키보드 가림을 확인한다.
- 본문·보조 텍스트·비활성·오류·포커스 대비는 구현 후 측정한다. 토큰을 적었다는 이유로 접근성 통과로 기록하지 않는다.
