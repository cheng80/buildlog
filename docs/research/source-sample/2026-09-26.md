## 수집 범위와 판단 기준

- 소스 경로별 GET 1회, Show HN 목록 응답의 상위 20개 item을 각 1회 조회했다. 총 **24회**, 리다이렉트·재시도 0회이며 원문 페이지·댓글·프로필은 요청하지 않았다. 402/403/차단이 없어 `insane-search` 대체 수집은 실행하지 않았다.
- 최신 **피드/API 응답의 제공순 상위 20건**씩 기록했다. GeekNews·itch.io는 각 50건 중 앞 20건, Ars Technica는 반환 20건 전부, Show HN은 134개 ID 중 앞 20개다. **전체 소스의 발행시각 기준 최신 20건을 보장하는 표본은 아니다.** 특히 itch.io 반환 순서에 날짜 역전이 있고 Show HN도 게시시각순이 아니므로, 표는 원래 순번을 보존했다. 나머지 항목을 다시 요청하거나 표본을 보충하지 않았다.
- ‘오늘’은 **2026-09-26 00:00 KST부터 각 수집 시각까지**다. 날짜는 Atom `published`, RSS `pubDate`, HN `time`을 KST로 통일했으며 수정일로 대체하지 않았다. 포럼 날짜는 **토론글 게시일**이고 연결된 외부 원문의 최초 게시일은 미확인이다. 피드의 날짜도 제공값이며 원문과 별도 대조하지 않았다.
- **[제안] 적합**: 앱·웹·게임 제작 소개, 개발 과정, 제작자가 활용할 개발·배포·자산 도구와 구체적인 작업 방식. 제작자 소개라는 이유로 1인·소규모 팀임을 추정하지 않았다. **[제안] 부적합**: 일반 산업·정책·소비자 소식, 개발 변경을 확인할 수 없는 할인·댓글 운영 안내. 제목·발췌로 관련성을 판정하지 못하면 **[미정] 보류**다. 이 분류는 공식 카드의 최종 채택·발행 승인이나 사실 검증이 아니다.
- 모든 표의 관찰 근거는 해당 절의 **확인 URL·확인 시각(KST)**에 수신한 피드/API다. 표의 원문·토론 링크는 응답에서 얻은 주소이며 직접 방문 성공을 뜻하지 않는다. 판정 근거는 요약한 한 구절만 남겼고, 원문 본문 전문·작성자 실명·이메일은 저장하지 않았다. 제목 안 인명은 `[인명 생략]`으로 가렸고 URL은 보존했다.
- **[미정] GeekNews 중복 범위**: 이번에 기록한 GeekNews 20건의 제목·짧은 발췌와 비교했다. 외부 원문 URL은 추출한 Atom 링크에 없어서 동일 원문 URL 대조를 완료하지 못했고, 반환된 나머지 30건도 비교하지 않았다. 따라서 `미확인`은 **이 20건에서 동일 사건을 찾지 못함**이며 **GeekNews 전체에 없음**을 뜻하지 않는다. GeekNews 자체 20건은 `해당(본소스)`로 표시하고 추가 중복 제거 건수와 구분한다.

쿼리 제거 시 `news.hada.io/topic?id=…`처럼 ID가 쿼리에 있는 서로 다른 글이 같은 주소로 합쳐진다. 따라서 토론 URL은 원래 ID를 보존해 식별하고, 정규화 일치만으로 중복 확정에 쓰지 않았다. 제목은 Show HN/Show GN 접두어·대소문자·공백 차이를 보정하고 번역된 제목의 제작물·사건을 사람이 대조했다. 제목상 동일 소개 확인과 URL 동일성 확인을 분리한다.
