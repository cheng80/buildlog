# Domain Docs

이 저장소는 `single-context` 구성을 사용한다. 도메인 용어는 루트 `CONTEXT.md`에, 설계 결정은 `docs/adr/`에 기록한다.

## 탐색 전에 읽을 문서

- 루트 `CONTEXT.md`에서 도메인 개념과 용어를 확인한다.
- `docs/adr/`에서 이번 작업 영역에 관련된 ADR을 읽는다.

파일이나 디렉터리가 아직 없으면 별도 안내 없이 작업을 계속한다. `/domain-modeling`이 실제로 용어나 결정을 확정할 때 필요한 문서를 생성한다. `/grill-with-docs`와 `/improve-codebase-architecture`도 이 스킬을 통해 문서를 작성한다.

## 파일 구조

```text
/
├── CONTEXT.md
└── docs/
    └── adr/
        └── 0001-<decision>.md
```

위 구조는 문서의 작성 위치를 정의하며, 빈 문서를 미리 만들 필요는 없다.

## 도메인 용어 사용

이슈 제목, 리팩터링 제안, 가설, 테스트 이름 등에서 도메인 개념을 표현할 때 `CONTEXT.md`에 정의된 용어를 사용한다. 용어집이 배제한 동의어로 바꾸지 않는다.

필요한 개념이 용어집에 없으면 기존 용어로 표현할 수 있는지 먼저 확인한다. 실제로 새로운 개념이 필요하면 `/domain-modeling`에서 다룰 누락 사항으로 기록한다.

## ADR 충돌

제안이 기존 ADR과 충돌하면 해당 ADR과 충돌 지점, 결정을 재검토할 이유를 명시한다. 예: “ADR-0007의 결정과 충돌하며, 재검토가 필요한 이유는 …”.
